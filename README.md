## Reproducibility Instructions for Reviewers

This repository contains the prototype source code, Kubernetes manifests, experiment scripts, and measurement data used in the manuscript.

### Requirements

The experiments were prepared for the following environment:

* Java 17+
* Maven Wrapper, included in `ai-client/`
* Python 3.10+
* Docker Desktop with Kubernetes enabled, or another local Kubernetes cluster
* `kubectl`

### 1. Clone the repository

```bash
git clone https://github.com/TimoBond/onnx-spring-boot-orchestrator.git
cd onnx-spring-boot-orchestrator
```

### 2. Build and test the Spring Boot ONNX component

```bash
cd ai-client
./mvnw test
./mvnw spring-boot:run
```

On Windows, use:

```bash
mvnw.cmd test
mvnw.cmd spring-boot:run
```

This step verifies the Java/Spring Boot part of the prototype, including ONNX Runtime integration and the decision logic.

### 3. Prepare the Python experiment environment

From the repository root:

```bash
cd target-app
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

On Windows:

```bash
cd target-app
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

### 4. Run the Kubernetes prototype

Apply the Kubernetes manifests:

```bash
kubectl apply -f ai-client/k8s/rbac.yaml
kubectl apply -f ai-client/k8s/target-workload.yaml
kubectl apply -f target-app/target-app-deploy.yaml
kubectl apply -f target-app/nodeport.yaml
```

Check that the pods are running:

```bash
kubectl get pods
kubectl get svc
```

### 5. Reproduce the load and monitoring runs

The following scripts can be used to reproduce the prototype-level load and monitoring experiments:

```bash
python target-app/load_gen.py
python target-app/monitor_loop.py
```

The CSV files in `target-app/` contain the recorded experimental outputs used for the manuscript tables and summary calculations. They can be inspected directly or regenerated by rerunning the corresponding scripts in the same environment.

### Notes

Small numerical differences are expected because latency measurements depend on the local machine, Docker/Kubernetes configuration, background system load, and JVM/Python warm-up state. The main reproducibility target is the same experimental workflow and the same relative comparison between the REST/Python sidecar path and the embedded ONNX/JVM path.
